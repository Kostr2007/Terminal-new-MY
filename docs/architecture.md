# Terminal New MY: архитектура

Terminal New MY добавляет общий язык интерфейса для повседневных команд.
Первый целевой стек: NixOS, fish, Kitty Material You. Обычный ANSI-терминал
остаётся поддерживаемой базой. Реализация v0.2 использует текстовую сетку;
нативные скругления карточек вывода и анимации Kitty пока не реализованы.

## Границы проектов

- **Kitty-Material-You** отвечает за окно, курсор, вкладки и нативную отрисовку.
- **Material-You-Terminal** генерирует палитру и оформление существующих приложений.
- **Terminal-new-MY** читает палитру, получает данные команд и представляет их
  через общие компоненты. Команда проекта — `tnmy`; `myt` остаётся генератором темы.

Код других проектов не копируется. Для независимых компонентов применяется MIT.
При будущих изменениях сторонних проектов сохраняются их собственные лицензии.

## Данные → компоненты → представление

`files.rs` читает файловую систему непосредственно. `palette.rs` проверяет
цветовые роли. `render.rs` создаёт вывод в истории, `browser.rs` — интерактивный экран,
`ui.rs` — поверхности, чипы, выделение и плотность. `worker.rs` даёт три
независимых фоновых задачи: каталог, превью, Git. Каждая имеет один pending-slot
и поколение запроса. Новое поколение отменяет работу и отбрасывает старые ответы.
Рабочий поток не присоединяется при выходе UI: заблокированная сетевая ФС
не задерживает закрытие. Загрузка — синхронная внутри своего потока, интерфейс
опрашивает только результаты и клавиатуру. В покое перерисовок нет.
Git-процессы ограничены дедлайном/размером; на Linux PR_SET_PDEATHSIG также
останавливает дочерний процесс при завершении родителя. `update.rs` делегирует выполнение `nh` через argv без shell.

В v0.2 один Rust package разделён на модули. Выделять workspace имеет смысл,
когда появится второй потребитель компонентов или независимый адаптер.

## Контракт палитры

Порядок поиска: `--palette` / `TNMY_PALETTE`, затем `MYT_PALETTE`,
`MYT_THEME_DIR/palette.json`, `themeDir` из `MYT_CONFIG` либо
`$XDG_CONFIG_HOME/material-you-terminal/config.json`, затем
`$XDG_STATE_HOME/material-you-terminal/theme/palette.json`.
Стандартные XDG-пути используются, когда переменные не заданы.

Формат совпадает с текущим `myt`: `{ "mode": "dark", "colors": { ... } }`.
Поддержаны `light` и `dark`; цвета — RGB hex. Проверяются все используемые роли,
чтобы не смешать тёмный запасной текст со светлой поверхностью.
При отсутствии автоматически найденной темы используется встроенная тёмная.
Явно заданный отсутствующий файл и повреждённая тема дают ошибку.
`tnmy doctor` показывает источник и предупреждение о запасной теме.

Новый запуск команды читает актуальную тему. Браузер перечитывает её при `r`
и изменении размера; непрерывного наблюдения и автоматической перекраски
неподвижного экрана в v0.2 нет.

## Представления и совместимость

- Обычный список остаётся в истории терминала.
- Полноэкранный браузер использует alternate screen и возвращает терминал
  при обычном выходе, ошибке, панике и обработанном Ctrl+C.
- Перенаправленный список не содержит украшений и не обрезает имена.
- `--json` возвращает метаданные; не-UTF-8 пути требуют `--zero`.
- `--zero` возвращает исходные Unix-байты путей с разделителем NUL.
- `NO_COLOR` и `--color never` отключают цвет; выделение браузера сохраняет
  текстовый маркер. Unicode и терминал с UTF-8 нужны для полного интерфейса.
- Непечатаемые управляющие символы экранируются в представлении; данные
  JSON и NUL-вывода не превращаются в визуально сокращённые имена.

Превью ограничено 64 KiB и 2000 строками, поддерживает прокрутку с учётом переноса строк. На Unix открытие выполняется с
`O_NOFOLLOW | O_NONBLOCK`, затем проверяется тип файла. Браузер не запускает
содержимое файлов и не читает устройства/FIFO как текст.

Каталог читается и сортируется в фоновом потоке; сортировка кеширует ключи
Unicode-имён. Фильтр использует готовые строчные имена. Виджеты строятся только
для видимой части списка. Клавиатура доступна во время загрузки.

`git.rs` читает porcelain v1 с NUL-разделителями, сохраняет исходные Unix-байты
путей, агрегирует изменённые вложения и проверяет корень при каждом переходе.
Кеш: 8 репозиториев, TTL 2 секунды; `r` обходит кеш. Бюджет: 600 ms / 2 MiB.
Неуспешный Git не превращает отсутствие результата в утверждение о чистом дереве.

`--pick` / `--pick-directory` используют stderr для интерфейса и stdout только
для выбранного NUL-пути. Fish `mycd` использует `string split0`, без eval и
без разбиения путей по строкам. При отмене путь не выводится.

## Темы и контраст

Цвета текста проходят проверку 4.5:1 на своей поверхности. Недостаточный
контраст заменяется `on_surface`, затем чёрным/белым; исходные роли не меняются.
`tnmy theme --check-contrast` показывает исходное и фактическое отношение.
Палитры matugen для трёх seed-цветов в двух режимах зафиксированы в tests/palettes.

`tool_themes.rs` экспортирует eza YAML, bat tmTheme, fzf color options и delta
config/argv. Отдельный кеш bat сохраняет пользовательские темы и синтаксисы.
Тема delta использует собственные цвета строк без зависимости от формата кеша bat.
Home Manager добавляет экспорт после генерации myt и через существующие hooks.
Это downstream-потребитель готовой палитры; новая генерация HCT не добавляется.

## Обновления

Обёртка сохраняет stdin/stdout/stderr дочернего `nh`: доступны его `nom`,
парольные запросы и логика активации. `tnmy` показывает заголовок и результат,
сохраняет exit code и сообщает сигнал как `128 + signal` на Unix.
Выполнение без `--refresh` не добавляет `--update`. С `--refresh` обновляются
входы flake. `--dry-run` только печатает argv и не запускает `nh`.

Полноценный экран обновлений требует отдельного адаптера событий Nix.
Будущий поток: `evaluation`, `download`, `build`, `activation`, `complete`,
`failure`, плюс ссылки на исходные сообщения. События `internal-json`
проверяются на закреплённых версиях. Этап активации нельзя выводить
из процента выполненных derivations. Неизвестное событие сохраняется в журнале.
